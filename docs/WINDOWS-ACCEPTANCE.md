# Перевірка ЛАД у Windows перед 1.0

Перевіряйте `Counter.exe` із ручної збірки потрібного коміту. Для дослідів використайте окрему папку з копією даних або тестовий JSON. Запишіть версію ЛАД, дату, версію Windows і результат кожного пункту. Неперевірений пункт залишається неперевіреним.

## Зібрана програма

У GitHub відкрийте Actions → Build Counter → Run workflow для гілки main. Збірка запускається лише вручну. Після завершення завантажте артефакти Counter та Windows-checks.

У `windows-checks.json` мають бути `platform: "win32"`, `status: "passed"` і потрібна версія. Цей запуск використовує окрему тимчасову базу: перевіряє відкриття зібраної програми, робочий IPC, обмін двома датами, пояснення, скасування, доступність, масовий табель, навчання та повторне читання бази. Він не підтверджує доставку системного сповіщення, появу вікна вибору файла, другий запуск EXE чи зовнішній вигляд.

## Перевірки на комп’ютері

| Перевірка | Дія та очікуваний результат |
|---|---|
| Перший запуск | Покладіть EXE в окрему папку без Counter-data та відкрийте. Віджет працює, журнал відкривається, налаштування показують потрібну версію. Немає порожнього вікна чи помилки. |
| Повторний запуск | Згорніть ЛАД і відкрийте той самий EXE знову. Уже відкрите вікно повертається; друга робоча копія програми не з’являється. Дані зберігаються. |
| Вибір копії | У «Дані» натисніть «Імпортувати копію». Відразу відкривається системний вибір JSON. Скасування нічого не змінює. Після вибору тестової копії підтвердження показує її склад. Імпорт, скасування імпорту та повторний вибір працюють. |
| Робочий сценарій | Запишіть відсутність майбутнього чергового з причиною. Перегляд показує призначення й завдання. Збереження створює місце для підміни. Виберіть підміну або обмін; перевірте «було → стане» і причину. Скасування повертає обидві дати обміну. |
| Захист | Заблокуйте тиждень, потім спробуйте записати відсутність цього чергового з окремої форми та масового табеля. Збереження зупиняється з поясненням. Виконане чергування також захищене. Скасування перегляду не змінює базу. |
| Пояснення після перезапуску | Збережіть підміну з причиною, закрийте й відкрийте EXE. Склад і «Чому я чергую?» містять ту саму причину, автора та обидві дати для обміну. |
| Сповіщення | У налаштуваннях увімкніть нагадування й натисніть їх перевірку. Створіть завдання з найближчим строком, дочекайтеся сповіщення з відкритим або згорнутим ЛАД. Натискання відкриває потрібне завдання; дії «Виконано» та «Через годину» працюють. Після перезапуску немає повтору вже надісланого нагадування. Якщо Windows блокує показ, перевірте її дозволи та «Не турбувати»; до успішного показу результат не зараховується. |
| Навчання | У «Довідці» пройдіть екскурсію та навчальний приклад. Перевірте підсвічування, назад/далі, згортання та Esc. Після завершення й дострокового виходу повертається власна база, без вигаданих людей і змін; попередня історія скасувань збережена. |
| Вигляд | Перевірте світлу й темну теми, збільшений текст, звичайне й максимізоване вікно, масштаб Windows 100% і 150%. Основні кнопки, строки та нижні кнопки діалогів видно, їх можна натиснути. |
| Оновлення | Збережіть JSON і копію всієї робочої папки. Закрийте ЛАД та замініть лише EXE, залишивши Counter-data поруч. Після запуску перевірте людей, документи, табель, графіки, пояснення, завдання й протоколи сірників. Новий запуск також зберігає ці дані. |
| Відновлення | Лише в окремій копії папки: закрийте EXE, перейменуйте основний counter-data.json і відкрийте програму. Дані відновлюються зі справної копії, видно повідомлення. Якщо в тестовій папці зробити всі копії непридатними, ЛАД пропонує вибрати власний JSON або закритися; повторний запуск не створює порожню базу. |

## Рішення щодо випуску

1. Звіт зібраного EXE пройшов і відповідає коміту та версії.
2. Усі ручні перевірки пройшли; до звіту додано дату та результати, за потреби — знімки екрана.
3. Виявлені помилки виправлено та повторно перевірено відповідний сценарій.
4. Лише після цього версія отримує позначку 1.0. Автоматичний звіт сам по собі її не надає.

ЛАД має працювати для доставки нагадувань. Закрита програма та вимкнений комп’ютер не надсилають їх; пропущені строки перевіряються під час наступного запуску.
