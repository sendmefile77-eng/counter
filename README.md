# Щоденний облік

Локальний Windows-віджет для щоденного обліку запитів працівників. Програма працює без мережі, не має телеметрії та зберігає робочі дані лише на комп'ютері користувача.

## Уже закладена логіка

- у налаштуваннях показується фактична версія запущеного застосунку; поточна версія — 0.9.0;
- статистика має три вкладки: огляд, працівники та документи; є швидкі періоди, вибір кількох людей, окремі групи активних і архівних працівників, порівняння з попереднім періодом тієї самої календарної тривалості та динаміка за днями/тижнями/місяцями;
- показники на картках і в таблиці працівників відкривають перевірний список дат або документів із джерелом, приміткою і переходом у табель; розшифровка має сторінки по 25 записів; отримані запити рахуються за датою документа, закриті дні — за табелем, а позначки без документа показуються окремо;
- майбутні дні не входять до результатів, норми чи незакритих днів; за відсутності норми відсоток не розраховується; загальне виконання — співвідношення сум днів, а не середнє відсотків людей; показано формулу та період порівняння;
- графік статистики використовує SVG із числовими розмірами, окремими кольорами запитів/інших завдань/відсутності/пропусків/днів без позначки та однаковою шкалою; нульові періоди мають порожні смуги, а натискання періоду розгортає його;
- таблицю статистики можна сортувати за будь-яким показником, шукати людей, показувати лише пропуски/дні без позначки/залишок та перемикати основні/всі колонки; ці фільтри таблиці не змінюють картки загального звіту; документи розділено на отримані у періоді та ті, що закрили його дні, включно з документами попередніх періодів;
- CSV статистики експортується окремо для працівників, динаміки й документів; містить період, вибраних людей, дату обмеження результатів та пояснення одиниць; старі розрахункові API збережено для сумісності;
- табель має режими місяця, тижня й довільного періоду до 366 днів, перехід до дати та сьогоднішнього дня, пошук працівників, фільтри пропусків/очікування/відсутності, показ архіву, компактні рядки та приховування неробочих днів;
- у табелі доступні виділення окремих клітинок через Ctrl, прямокутника через Shift, цілого рядка чи дня; Shift зі стрілками розширює вибір; є масова зміна статусів, очищення ручних позначок, створення індивідуальних робочих вихідних і повернення їх у вихідні;
- масова операція охоплює вибрані клітинки або кількох працівників у заданому періоді з фільтром днів тижня; можна не замінювати наявні статуси та явно включати неробочі дні; перед застосуванням видно зміни, конфлікти і причини пропусків; у великих списках показано перші 250 клітинок кожної категорії, а кількість охоплює всі;
- записи за документами захищені; відсутність не встановлюється на призначене чергування в будь-якому графіку; за замовчуванням конфлікт зупиняє всю операцію, а пропуск заблокованих клітинок дозволяється окремим прапорцем; зміна даних після перевірки вимагає нового перегляду; вся операція скасовується одним кроком;
- очищення прибирає ручні позначки, а автоматичний пропуск треба виправляти новим статусом; минулі незакриті дні можуть повторно закритися як пропуски; повернення індивідуального вихідного прибирає його позначку і робочий режим, але не зачіпає дні з документами;
- табель показує підсумки у днях для кожного працівника та всіх показаних рядків; майбутні дні не збільшують «Очікує»; експорт CSV містить відкритий період, показаних працівників, усі дати, позначення та підсумки, з UTF-8 BOM для Excel;
- стриманий інтерфейс «Executive Graphite»: ієрархія графітових поверхонь, єдина система векторних іконок, виразний поточний день, компактні стани керування та короткі анімації з підтримкою системного режиму зменшеного руху;
- до 15 активних працівників у компактному круглому віджеті без прямокутної рамки;
- довільне переміщення віджета та зміна його розміру від 260 до 700 пікселів зі збереженням позиції;
- один запит зазвичай закриває один робочий день;
- складний запит за окремим дозволом може закривати два робочі дні;
- перша одиниця закриває поточний день, решта — найближчі попередні незакриті дні, рухаючись назад від учора;
- нерозподілений залишок можна за окремим підтвердженням зарахувати назад або наперед;
- майбутні дні ніколи не закриваються автоматично: програма запитує окреме підтвердження;
- час автоматичного закриття робочого дня налаштовується; функцію можна вимкнути;
- зранку віджет показує стан нового дня, тому вчорашній червоний сектор знову стає сірим, а сам пропуск залишається в історії;
- окремі статуси для інших завдань, особистих справ, лікарняного, відпустки та відгулу;
- субота й неділя автоматично позначаються «ВХ», але конкретний вихідний можна вручну зробити робочим днем для працівника;
- табель за місяць, ручна позначка «Подав» за минулий день, текстова аналітика та підрахунок відпрацьованих днів;
- статус для працівника можна встановити одразу на період робочих днів; перед застосуванням програма показує кількість дат і зупиняє всю дію, якщо хоча б один день уже пов’язаний із документом;
- перед зарахуванням кількох запитів видно дати, які вони закриють; документ можна виправити з попереднім переглядом нового розподілу, а вже дозволений розподіл залишку після виправлення підтверджується повторно;
- працівники з архіву не показуються в поточному табелі, але їхня історія зберігається в базі та експорті;
- ім’я та порядок активних працівників можна виправити без видалення їхньої історії;
- ручне відновлення історії в табелі за дати до першого запуску без автоматичного створення пропусків за весь минулий період;
- окремий модуль чергувань: початково по двоє щодня; у правилах можна задати від 0 до 15 людей, окремо для буднів, вихідних і кожного дня тижня; нуль вимикає чергування цього дня;
- можна створювати, перейменовувати, перемикати й видаляти кілька незалежних графіків чергувань; у кожного власні учасники, календар, обмеження, історія, Σ/Р і генерація, а наявний старий графік автоматично стає «Основним»;
- початкові Σ і Р вводяться один раз станом на кінець поточного тижня; наступні дежурства автоматично збільшують їх, а 1 січня річний підрахунок починається з нуля;
- окремий вибір учасників графіка без обов’язкового включення всіх працівників програми;
- архівування або вилучення учасника одразу прибирає його з поточних і майбутніх призначень, але не змінює історію минулих днів;
- кожен рядок працівника має власний колір і помітну горизонтальну лінію по всій ширині таблиці; натискання на ім’я закріплює виділення рядка, а понеділки відокремлені вертикальною межею;
- горизонтальну прокрутку графіка можна довести до положення, у якому закріплені імена залишаються ліворуч, а поруч відображається останній тиждень місяця;
- у «Налаштуваннях» реально змінюються час і режим закриття дня, робочі дні, поведінка віджета, розміри таблиці, виразність кольорових ліній, кольори статусів, підтвердження, показ архіву та кількість щоденних резервних копій; легенду винесено в окрему «Довідку»;
- правила задаються для кожного графіка окремо: 0–15 людей на день, 0–30 повних днів відпочинку, бажаний або обов’язковий інтервал, перерва на 1–8 уікендів, тижневий ліміт (0 — без окремого ліміту), пріоритет розподілу, кількість для компенсації та ціль наступного тижня, період історії пар і поведінка за нестачі людей;
- вікно правил використовує числові поля та видимі варіанти вибору без випадаючих меню; кнопка збереження завжди доступна, а зведення показує кількість місць і суперечності між правилами; порожнє поле окремого дня успадковує загальне правило, а «Початкові правила» заповнює форму без негайного збереження;
- перед формуванням показується попередній перегляд усіх семи днів; у ньому можна закріпити конкретних людей на вільні місця, перерахувати результат і побачити причини нестачі; база змінюється лише після застосування;
- якщо додатковий пошук варіантів досяг ліміту, попередній перегляд прямо повідомляє, що можливість заповнити дефіцитний день остаточно не виключена;
- кожне нове призначення зберігає пояснення з датою, правилами на той момент, навантаженням усіх учасників, попереднім чергуванням, тривалістю відпочинку, місцем у черзі та історією всіх пар; у картці працівника є «Чому я чергую цього дня» і копіювання пояснення;
- для нового розрахунку до семи днів пояснення перевіряє заміну конкретного чергового кожним іншим учасником: показує порушене правило або перший критерій, який погіршиться, з числами до/після; рівноцінні заміни позначаються прямо; перед збереженням генератор додатково шукає покращення заміною однієї людини, зберігаючи ручні закріплення;
- ручне призначення має окреме поле причини; воно не видається за автоматичний вибір; зміна правил не переписує збережене пояснення, а для старих призначень без доказового запису програма прямо позначає відновлення за поточними даними;
- для конкретного дня можна дозволити разовий виняток, не послаблюючи правила всього графіка;
- завершений тиждень можна заблокувати від випадкових змін і за потреби розблокувати;
- графік можна скопіювати разом з учасниками та правилами, але без старих призначень і статистики;
- аналітика справедливості показує навантаження, чергування у вихідні, середній відпочинок і повтори пар;
- клік по порожній клітинці швидко призначає чергування; клік по зайнятій відкриває окремі команди для позначення виконання та зняття призначення;
- правий клік відкриває «А», відсутності, жовту заборону планування без впливу на статистику та примусове зняття чергування;
- можна вибрати будь-який тиждень за датою або перейти до першого незаповненого; попередній перегляд передує застосуванню, готові дні та ручні призначення не перераховуються;
- вибраний тиждень можна очистити повністю або прибрати лише автоматичні призначення зі збереженням ручних і реалізованих; дію можна скасувати; обидва режими стосуються тільки активного графіка й залишають «А», відсутності, заборони та правила;
- циклічний генератор продовжує чергу після вручну внесеної історії, вирівнює навантаження всередині нового тижня, компенсує два чергування тим, хто мав одне попереднього тижня, не пропускає доступних учасників і починає нове коло з 1 січня;
- окрема сторінка «Відпросився» з датою, точним часом виходу й повернення, автоматичною тривалістю, напрямком/причиною та приміткою; є фільтри за працівником, періодом і текстом причини; ці короткі відлучення не змінюють табель і відпрацьовані дні;
- відлучення можна редагувати; програма не дозволяє записати два відлучення однієї людини з часом, що перетинається;
- у віджеті є режим списку, у табелі й графіку можна переходити між клітинками стрілками та відкривати дії клавішею Enter;
- аналітика показує помісячну динаміку та експортує звіт за вибраний період;
- повний імпорт/експорт резервної копії JSON і табличний експорт CSV, включно з усіма окремими графіками та журналом «Відпросився»;
- у налаштуваннях можна переглянути й відновити локальну резервну копію; при пошкодженні основного файлу програма перевіряє попередню та щоденні копії, зберігаючи пошкоджений файл окремо;
- повне обнулення всіх локальних даних із подвійним підтвердженням.

Відпрацьованими вважаються дні, закриті запитом, і дні зі статусом «Залучений до інших завдань». Особисті справи, лікарняний, відпустка, відгул та святкові дні показуються окремо і не збільшують лічильник відпрацьованих днів.

Тиждень із порожнім місцем у чергуваннях лишається в черзі для повторного перегляду. Якщо доступність людей змінилася, неповний автоматичний день можна сформувати повторно: попередній автоматичний вибір дозволено замінити, а внесених вручну чергових і повністю готові дні генератор не чіпає. Уже призначеного на завтра працівника генератор не ставить сьогодні, якщо діє заборона чергувань поспіль. Заблокований вручну тиждень пропускається під час пошуку наступного тижня.

Наведений нижче порядок розподілу описує початкові правила. У вікні «Правила графіка» можна змінити кількість людей, обмеження й пріоритети; для перебудови готових днів спочатку очистіть тиждень.

У графіку чергувань календарні вихідні залишаються звичайними днями графіка. Працівник не потрапляє до розподілу, якщо його виключено зі складу учасників або для нього позначено вихідний, відпустку, лікарняний, відгул, особисті справи, «А» чи жовту заборону планування. Жовта позначка не є відсутністю та не входить до жодної статистики. Після «А» чергування наступного дня дозволене, але після чергування не можна ставити «А» на наступний день. Якщо «А» уже внесено, програма не призначить цю людину черговою напередодні. Генератор продовжує циклічну чергу за останніми вручну внесеними чергуваннями, тимчасово пропускає відсутнього та повертає його в чергу після появи. Автоматичне призначення однієї людини два календарні дні поспіль заборонене жорстко. Так само генератор не ставить людину у два сусідні календарні вікенди; якщо склад без такого повтору неможливий, місце лишається порожнім. Увесь новий календарний тиждень оптимізується одним блоком, щоб ранні призначення не створювали штучної нестачі наприкінці тижня. Якщо через жорсткі правила другого допустимого чергового немає, програма залишає місце порожнім і підсвічує всю колонку дня червоним. Натискання на цю колонку відкриває склад дня: там можна додати другого працівника або явно дозволити чергування одного. Ручні призначення є незмінними обмеженнями моделі: генератор може лише заповнити вільне друге місце, але ніколи не прибирає й не замінює обрану вручну людину. Готові автоматичні дні також не перераховуються повторним натисканням кнопки. Стара різниця в кількості не виключає працівника з нового кола. Якщо працівник мав одне чергування в попередньому календарному тижні, модель надає йому пріоритет на два в наступному; при цьому тижневий розподіл усе одно не повинен мати різницю понад одне чергування за достатнього складу. Історія пар у поточному році враховується під час кожного нового формування, тому модель спершу шукає ще не використані поєднання співробітників і лише за відсутності рівноцінної альтернативи повторює пару. Модель лексикографічно мінімізує: кількість порожніх місць, нерівність кількості чергувань у новому тижні, невиконану компенсацію попереднього тижня, порушення двох повних днів відпочинку, повтор уже використаної пари та відхилення від циклічної черги. Тобто рівномірність має вищий пріоритет за бажаний дводенний проміжок, але заборона двох календарних днів поспіль завжди залишається жорсткою. За восьми доступних учасників і 14 тижневих місць результатом мають бути шість людей із двома чергуваннями та двоє з одним, якщо ручні позначки й відсутності не роблять це неможливим. Статистика, історія пар і черга рахуються окремо для кожного календарного року; при переході року контрольна дата переноситься на 31 грудня, тому вже внесені січневі дежурства не губляться.

## Запуск для розробки

Потрібен Node.js 24 або новіший.

```bash
npm install
npm test
npm start
```

## Збірка для Windows

```bash
npm install
npm run dist:win
```

У каталозі `dist` буде створено переносимий файл `Counter.exe`, який не потребує інсталятора. У GitHub Actions він завантажується як артефакт `Counter`.

## Зберігання даних

Поруч із переносимим `Counter.exe` автоматично створюється папка `Counter-data`. У ній розміщуються основний файл `counter-data.json`, попередня резервна копія та налаштовувана кількість щоденних копій у папці `backups`. Під час першого запуску нової версії наявна база зі старого системного каталогу Windows автоматично копіюється до цієї папки. Для додаткової резервної копії або перенесення між комп'ютерами можна використовувати експорт та імпорт JSON.
