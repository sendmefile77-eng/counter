# ЛАД — Люди. Аналітика. Документи.

Локальний Windows-застосунок для обліку роботи співробітників, проєктів, табеля, чергувань і завдань керівника. Програма працює без мережі, не має телеметрії та зберігає робочі дані лише на комп'ютері користувача.

## Що нового у 0.18.0

- У «Наявності» права кнопка на клітинці відкриває меню конкретного працівника й дати: дев’ять статусів, зміна дня або періоду та видалення позначки. Поточний статус відмічено; для порожнього дня видалення недоступне. Дія відкриває форму з вибраним статусом, підставою, перевіркою наслідків і можливістю скасувати збереження.
- Меню працює у місяці, тижні, кварталі та перегляді дня. Shift+F10 або клавіша контекстного меню відкриває його з клавіатури; стрілки обирають дію, Enter підтверджує, Escape закриває. Меню залишається в межах вікна й закривається при натисканні поза ним, прокручуванні чи переході між розділами.
- ЗКП не додає день до зарахованої роботи, навіть якщо є активна або завершена робота. Після повернення в офіс позначте «На роботі» на дату повернення й відкрийте «Прийняти роботу за дні ЗКП» у діях працівника. Виберіть дні, за які принесено роботу, та введіть пояснення. Дні ЗКП не вибираються автоматично. Перевірка й підтвердження зберігають дату, пояснення та автора; скасування повертає всю операцію. Позначка ЗКП залишається в наявності, у табелі підтверджений день має символ «ЗКП✓».
- «Навчання онлайн» та «Навчання Академія» доступні у формі й меню наявності. Обидва дозволяють чергування; навчання рахується окремо від зарахованої роботи та пропусків. Статистика й CSV показують навчання, дні ЗКП та дні ЗКП, що очікують здачі.
- Картка «Роботу зараховано» та лічильник віджета враховують підтверджені дні. Присутність і поточна робота самі по собі не додаються до цього лічильника.
- Потрібно вручну зібрати новий EXE. Схема копії — 13; старі копії залишаються сумісними.

## Що нового у 0.17.0

- Компактна «Наявність»: основний перегляд — місяць, також тиждень, квартал із трьома місяцями та день. Стрілки перемикають періоди, календарна клітинка відкриває день працівника, заголовок місяця у кварталі — сам місяць. Пошук і невеликі лічильники за вибраною датою; пояснення та історія згорнуті. Пріоритет наявності для всіх розділів і допуск ЗКП до чергувань збережено.
- Планувальник показує лише завдання. Компактні панелі періоду й фільтрів, 6 кольорів карток, до 5 власних міток; пошук враховує мітки. Колір і мітки зберігаються в копії, історії змін і повторюваних завданнях. Строк і стан показано окремо від вибраного кольору.
- Рядки графіка чергувань мають помітніший фон у кольорі працівника. Кольорові розділювачі, вибір рядка та кольори статусів залишаються читабельними.
- Працівника з архіву можна видалити після перегляду пов’язаного обліку та наслідків. Його позначки, роботи, відлучення, початкові підсумки й призначення в усіх графіках видаляються. Завдання зберігаються; відкриті без виконавця переходять у «Потрібне рішення». Імена у збережених жеребкуваннях залишаються фактом на час розіграшу. Дія підтримує скасування.
- У «Тягнути сірник» довша анімація: перемішування, пауза, повільне витягування, світлові промені й іскри. При одному виконавці — близько 9 секунд, при кількох — до 17. Пропуск, закриття, згортання та зменшений рух показують той самий уже збережений результат.
- Завершені протоколи можна видаляти з історії або відкритого протоколу. Відкрите пов’язане завдання спочатку потрібно виконати або скасувати. Завдання й причини повторних розіграшів зберігаються, номери не використовуються повторно після перезапуску чи відновлення копії. Видалення підтримує скасування.
- Версія — 0.17.0, схема даних — 12; старі копії мігрують автоматично. EXE збирається вручну.

## Що нового у 0.16.0

- Окремий розділ «Наявність»: на роботі, ЗКП, відпустка, лікарняний, відгул, особисті справи, неробочий день. Позначка для одного або кількох працівників на день чи період до 366 календарних днів. Є перегляд за днем і тижнем, пошук, фільтри та історія з підставою, автором і часом.
- «Наявність» має пріоритет над ручним обліком роботи, активними проєктами й автоматичними пропусками. Відсутність не додає невідпрацьованих днів. «На роботі» та ЗКП враховуються як повноцінні робочі дні за календарем; ЗКП дозволяє чергування. Прогрес і завершення проєктів залишаються окремими фактами.
- Генератор, ручне призначення, підміни та обміни перевіряють одну модель наявності. Відсутність блокує чергування і у вихідні. Перед записом показуються наслідки для всіх графіків і завдань; заплановані призначення знімаються з причиною й залишають місця для заміни. Минулі, виконані й заблоковані чергування захищені від автоматичного переписування.
- Табель, віджет, аналітика, тижневе зведення й CSV враховують наявність. У повній таблиці аналітики окремо видно дні на роботі та ЗКП. Майбутні позначки — план, до фактичних днів вони не додаються. Нове жеребкування виключає відсутніх сьогодні; збережені протоколи не змінюються.
- Старі позначки відсутності доступні в новому розділі без перезапису історії. JSON-схема 11 зберігає нові позначки; імпорт, локальні копії та скасування підтримують їх. Очищення наявності повертає попередній облік роботи й прибирає стару позначку відсутності. Після очищення минулий день без роботи може знову потребувати позначки.
- Версія застосунку — 0.16.0. Збірка EXE запускається вручну; нативний запуск та файловий вибір перевіряються у Windows за інструкцією.

## Що нового у 0.15.0

- Облік документів замінено обліком роботи співробітників. Нову роботу задають опис, працівник, кількість проєктів, початок, незалежна оцінка тривалості та орієнтовна дата завершення. Вносити документи, зараховувати запити чи розподіляти залишки через інтерфейс більше не потрібно.
- Прогрес — загальна кількість виконаних проєктів. Робота триває до підтвердженого завершення або скасування фактичною датою; навіть 5/5 не завершує її автоматично. Після орієнтовного строку ЛАД просить перевірити роботу, без автоматичних пропусків. Зміни строку й обсягу, зменшення прогресу та скасування зберігають пояснення, автора й історію.
- Табель і статистика використовують періоди роботи з пріоритетом ручних позначок та відсутності. Вихідні враховуються за календарем; кілька робіт не множать один день. Майбутні дні не входять до фактичного обліку. Проєкти у завершених роботах рахуються за датою підтвердженого завершення; частковий прогрес видно в списку робіт.
- Статистика має динаміку, співробітників і дати, швидкі періоди, групи, вибір людей, порівняння та перевірку показників за фактами. CSV експортується за людьми, динамікою або днями. Тижневе зведення й PDF також показують роботу замість запитів. Відсоток днів з обліком не подається як оцінка продуктивності.
- Віджет має збережені режими «Команда / Чергування / Завдання», круглий вигляд або прямокутну панель, список співробітників і видимі повідомлення про прострочені завдання, місця для підміни та перегляд строків роботи. Дії: додати роботу, завдання, відсутність, скасувати останню зміну. Звичайний клік відкриває дії; швидке позначення відпрацьованого дня вмикається окремо.
- Доступні прилипання до країв і фіксація положення та розміру. «Сховати» залишає ЛАД у системному треї, «Вийти з ЛАД» завершує програму. Меню трея відкриває віджет або повне вікно ЛАД; Ctrl+Shift+L повертає віджет із будь-якої програми, якщо комбінація доступна. Якщо трей недоступний, приховування згортає вікно в панель завдань.
- JSON-схема 10 додає роботи й налаштування віджета. Старі копії зберігають документи, зараховані дні, графіки, завдання, протоколи та історію; новий інтерфейс не створює нових документів. Імпорт файла, локальні копії й скасування перевірено також для нових робіт. Версія застосунку — 0.15.0; запуск EXE та нативну поведінку трея й гарячої клавіші треба підтвердити у Windows.

## Що нового у 0.14.3

- Кнопка «Імпортувати копію» відкриває файловий вибір безпосередньо з натискання, до асинхронних обробників інтерфейсу. Обраний файл читається локально та передається на перевірку бази без повторного виклику файлового діалогу через IPC.
- JSON-копію можна перетягнути в блок «Відновлення», зокрема якщо системний вибір файла не відкривається. Імпорт одного файла, повторний вибір тієї самої копії, скасування та помилки не залишають кнопку заблокованою. Стан імпорту зберігається під час фонового оновлення екрана, а пояснення помилки видно в самому блоці.
- На час системного підтвердження вимикається режим «поверх усіх вікон»; після закриття діалогу він відновлюється відповідно до поточних налаштувань. Це також застосовується до старого системного шляху вибору копії.
- Обидва способи імпорту використовують однакову перевірку JSON, сумісності схеми та пов’язаних даних. Збережено підтвердження з кількістю записів, локальну копію попередньої бази, скасування імпорту та блокування імпорту в навчанні. Додано регресійні тести нового шляху й перевірку читання файла у самоперевірці Windows-збірки. Відображення самого системного файлового діалогу залишається ручною перевіркою Windows.

## Що нового у 0.14.2

- У «Тягнути сірник» після збереження протоколу спички перемішуються, короткі спички витягуються по черзі, а імена виконавців поступово відкриваються. Показ триває приблизно 3–6 секунд і використовує вже збережений результат.
- «Показати результат», Esc або закриття вікна пропускають анімацію без нового розіграшу. Якщо ввімкнено системне зменшення руху, результат показується одразу. Перехід до іншого діалогу прибирає таймери; запізніле збереження не відкриває анімацію поверх іншої роботи.
- Під час збереження та показу повторне натискання не створює другого протоколу. Поля й вибір учасників захищені до завершення; пошук і перегляд попередніх протоколів залишаються доступними під час збереження. Табель, графік і спосіб випадкового вибору не змінено.

## Що нового у 0.14.1

- Перевірено всі 12 розділів і основні діалоги у світлій та темній темах, зі збільшеним текстом і в різних розмірах вікна. У формах відлучень поля часу більше не тісняться; у невеликому вікні блоки огляду дня та дії з працівниками перебудовуються без накладання.
- У пошуку «Знайти або перейти» заголовок і нижня підказка залишаються видимими, а результати прокручуються окремо. Нижні кнопки діалогів переносяться, довгі назви й пояснення не виштовхують інші елементи. Кнопки збереження налаштувань повністю поміщаються у вікні.
- Фонове оновлення зберігає текст, вибрані значення, фокус і курсор у формах додавання працівника, відлучення та періоду табеля. Після успішного додавання форма очищається; помилка залишає введені дані для повторної спроби.
- Під час збереження видно індикатор, повторна відправка тієї самої форми не створює другого працівника, документа, завдання чи відлучення. Якщо користувач закрив діалог і відкрив інший, запізніла відповідь не підміняє нове вікно.
- Перевірка документа не дозволяє зберегти змінену після запиту форму за старою відповіддю. Після редагування потрібно перевірити актуальні дані; закритий діалог не оновлюється запізнілим результатом.
- Перегляд складу дня та попередній розрахунок графіка показують завантаження. Скасований перегляд не відкривається повторно після отримання відповіді; невдалий розрахунок прибирає індикатор і повідомляє про помилку.
- «Змінити ім’я» й «До архіву» мають однозначні підписи. Коли всі 15 місць зайняті, додавання заблоковано з поясненням. Кнопки зміни порядку мають зрозумілі назви для клавіатури та читача екрана. У згорнутій бічній панелі видно кількість питань у «Наслідках змін».
- Повідомлення можна закрити кнопкою; читання з фокусом або вказівником зупиняє їх автоматичне зникнення. Виправлено кольори вибраних варіантів масового табеля та підказок у світлій темі, узгоджено вигляд полів і збільшений текст у календарі. Робочі дані та правила розрахунку не змінено.

## Що нового у 0.14.0

- Єдина перевірка доступності для окремого працівника, періоду та масового табеля: усі графіки, зачеплені завдання, причина, захист виконаних і заблокованих чергувань. Масова зміна показує склад «було → стане», залишає місця для підміни та скасовується одним кроком. Вибрані клітинки й календарні фільтри зберігають свій точний обсяг; пропуск конфліктів потребує явного вибору.
- Захист від застарілих перевірок: зміна даних або умов вимагає нового перегляду. Старі прямі команди запису відсутності й архівування більше не обходять перевірку наслідків.
- Якщо заміни немає, ЛАД пояснює наступну дію залежно від причини: перевірка виконання, блокування, відпочинку, тижневого ліміту чи доступності. Для порожнього результату фільтрів є «Показати всі варіанти». Пояснення обміну із заповненням вільного місця показує фактичну кількість чергових до та після для обох дат.
- Перед імпортом і відновленням зберігається окрема копія попередньої бази, яка переживає наступні звичайні зміни. Кількість щоденних копій і таких копій обмежується окремо налаштуванням 1–30; додатково залишається попереднє збереження. При резервному пошуку враховується час копій.
- Після пошкодження чи зникнення основного файла програма шукає справну копію, зберігає пошкоджений файл для перевірки й показує повідомлення у віджеті та журналі. Якщо справної копії немає, наступний запуск не створює порожню базу: можна вибрати власний JSON або закрити ЛАД. Новішу несумісну схему програма не перезаписує старішими даними. Старий каталог Windows не підміняє актуальні резервні копії.
- У «Довідці» є екскурсія з підсвічуванням кнопок, кроками назад/далі, згортанням підказки та виходом через Esc. Для нової порожньої бази є стартова пропозиція навчання. Окремий навчальний приклад із вигаданими людьми проводить через лікарняний, підміну, збережене пояснення й передачу завдання. Робоча база та її історія скасувань зберігаються окремо; вихід повертає їх без навчальних змін. Системні нагадування на час вправи вимкнені.
- Ручна Windows-збірка перевіряє вже зібраний `Counter.exe` через справжній процес Electron, інтерфейс і IPC в окремій тимчасовій базі. Артефакт `Windows-checks` містить версію, платформу, результати та перелік перевірок, які залишилися ручними. Автоматичних запусків збірки немає.
- Версія 0.14.0 відображається у налаштуваннях і бічній панелі. JSON-схема сумісна з 0.13.0. Фактичний запуск EXE, системний вибір файла, доставку сповіщень і повторний запуск треба підтвердити у Windows за [протоколом перевірки](docs/WINDOWS-ACCEPTANCE.md), перш ніж позначати випуск як 1.0.

### Як працюють сповіщення Windows

ЛАД має залишатися запущеним, зокрема у згорнутому стані. При повному закритті або вимкненому комп’ютері сповіщень немає; при наступному запуску програма перевіряє пропущені строки. Автозапуск і фонове продовження після закриття не вмикаються.

Для системних сповіщень портативна програма створює ярлик «ЛАД» у меню «Пуск» поточного користувача, спрямований на початковий `Counter.exe`. Це не інсталятор і не окреме сховище робочих даних. Windows може блокувати сповіщення своїми дозволами або режимом «Не турбувати»; перевірте їх кнопкою в налаштуваннях. Навіть якщо Windows не показує сповіщення, завдання залишаються в огляді, планувальнику й віджеті. Реальна робота системних сповіщень і друку потребує перевірки у Windows після ручного складання EXE.

## Робочий простір ЛАД

ЛАД має впізнавану айдентику: синьо-сталевий знак, золотий акцент, спокійні робочі поверхні та згруповану навігацію. На огляді дня видно статуси команди, склад чергових із поясненням, активні роботи та прогрес проєктів, пошук і фільтри. Проєкти й дні роботи показуються окремо; неробочий день без окремої робочої позначки не потрапляє до очікування.

У налаштуваннях доступні «Нічний ЛАД» і «Світла сталь», комфортна або компактна щільність та збільшений текст. Попередній перегляд вигляду працює одразу; зміни зберігаються лише кнопкою «Зберегти». Незбережені налаштування залишаються чернеткою під час переходу між розділами, їх можна скасувати. Наявні бази отримують стандартний вигляд без зміни робочих даних.

- `Ctrl+K` — знайти розділ або працівника; стрілки й `Enter` керують вибором.
- `Ctrl+1` … `Ctrl+8` — перейти до розділу відповідно до порядку навігації.
- `Esc` — закрити діалог; `Tab` та `Shift+Tab` залишають фокус усередині нього.
- `F11` — повний екран; діалоги повертають фокус на елемент, який їх відкрив.

Основні операції табеля та графіка доступні без розкриття додаткових блоків. Виділення клітинок, керування графіком і очищення тижня мають окремі підписані блоки. Правила, попередній перегляд, пояснення призначень, захист історичних записів і скасування дій працюють як раніше. Переносимий файл і папка даних зберігають назви `Counter.exe` та `Counter-data` для сумісності з наявними копіями.

- записи за документами захищені; відсутність не встановлюється на призначене чергування в будь-якому графіку; за замовчуванням конфлікт зупиняє всю операцію, а пропуск заблокованих клітинок дозволяється окремим прапорцем; зміна даних після перевірки вимагає нового перегляду; вся операція скасовується одним кроком;
- очищення прибирає ручні позначки, а автоматичний пропуск треба виправляти новим статусом; минулі незакриті дні можуть повторно закритися як пропуски; повернення індивідуального вихідного прибирає його позначку і робочий режим, але не зачіпає дні з документами;
- табель показує підсумки у днях для кожного працівника та всіх показаних рядків; майбутні дні не збільшують «Очікує»; експорт CSV містить відкритий період, показаних працівників, усі дати, позначення та підсумки, з UTF-8 BOM для Excel;
- стриманий інтерфейс «Executive Graphite»: ієрархія графітових поверхонь, єдина система векторних іконок, виразний поточний день, компактні стани керування та короткі анімації з підтримкою системного режиму зменшеного руху;
- до 15 активних працівників у круглому віджеті чи прямокутній панелі;
- переміщення віджета, прилипання до країв та фіксація, зміна його розміру від 260 до 700 пікселів зі збереженням позиції;
- час автоматичного позначення робочого дня без обліку налаштовується; функцію можна вимкнути;
- окремі статуси «У роботі», «Відпрацьовано», «Інша робота», особисті справи, лікарняний, відпустка та відгул;
- субота й неділя початково неробочі; календар налаштовується, окремий вихідний можна зробити робочим для співробітника;
- масові позначки табеля проходять перевірку доступності, графіків та захищених історичних записів;
- працівники з архіву не показуються в поточному табелі, але їхня історія зберігається в базі та експорті;
- ім’я та порядок активних працівників можна виправити без видалення їхньої історії;
- ручне відновлення історії в табелі за дати до першого запуску без автоматичного створення пропусків за весь минулий період;
- окремий модуль чергувань: початково по двоє щодня; у правилах можна задати від 0 до 15 людей, окремо для буднів, вихідних і кожного дня тижня; нуль вимикає чергування цього дня;
- можна створювати, перейменовувати, перемикати й видаляти кілька незалежних графіків чергувань; у кожного власні учасники, календар, обмеження, історія, Σ/Р і генерація, а наявний старий графік автоматично стає «Основним»;
- початкові Σ і Р вводяться один раз станом на кінець поточного тижня; наступні чергування автоматично збільшують їх, а 1 січня річний підрахунок починається з нуля;
- окремий вибір учасників графіка без обов’язкового включення всіх працівників програми;
- архівування або вилучення учасника одразу прибирає його з поточних і майбутніх призначень, але не змінює історію минулих днів;
- кожен рядок працівника має власний колір і помітну горизонтальну лінію по всій ширині таблиці; натискання на ім’я закріплює виділення рядка, а понеділки відокремлені вертикальною межею;
- горизонтальну прокрутку графіка можна довести до положення, у якому закріплені імена залишаються ліворуч, а поруч відображається останній тиждень місяця;
- у «Налаштуваннях» реально змінюються час і режим закриття дня, робочі дні, поведінка віджета, розміри таблиці, виразність кольорових ліній, кольори статусів, підтвердження, показ архіву та кількість щоденних резервних копій; легенду винесено в окрему «Довідку»;
- правила задаються для кожного графіка окремо: 0–15 людей на день, 0–30 повних днів відпочинку, бажаний або обов’язковий інтервал, перерва на 1–8 уікендів, тижневий ліміт (0 — без окремого ліміту), пріоритет розподілу, кількість для компенсації та ціль наступного тижня, період історії пар і поведінка за нестачі людей;
- вікно правил використовує числові поля та видимі варіанти вибору без випадаючих меню; кнопка збереження завжди доступна, а зведення показує кількість місць і суперечності між правилами; порожнє поле окремого дня успадковує загальне правило, а «Початкові правила» заповнює форму без негайного збереження;
- перед формуванням показується попередній перегляд усіх семи днів; у ньому можна закріпити конкретних людей на вільні місця, перерахувати результат і побачити причини нестачі; база змінюється лише після застосування;
- якщо додатковий пошук варіантів досяг ліміту, попередній перегляд прямо повідомляє, що можливість заповнити дефіцитний день остаточно не виключена;
- кожне нове призначення зберігає пояснення з датою, правилами на той момент, навантаженням усіх учасників, попереднім чергуванням, тривалістю відпочинку, місцем у черзі та історією всіх пар; у картці працівника є «Чому я чергую цього дня» і копіювання пояснення;
- для нового розрахунку до семи днів пояснення перевіряє заміну конкретного чергового кожним іншим учасником: показує порушене правило або перший критерій, який погіршиться, з числами до/після; рівноцінні заміни позначаються прямо; перед збереженням генератор додатково шукає покращення заміною однієї людини, зберігаючи ручні закріплення;
- ручне призначення має окреме поле причини; воно не видається за автоматичний вибір; зміна правил не переписує збережене пояснення, а для старих призначень без доказового запису програма прямо позначає відновлення за поточними даними;
- для конкретного дня можна дозволити разовий виняток, не послаблюючи правила всього графіка;
- завершений тиждень можна заблокувати від випадкових змін і за потреби розблокувати;
- графік можна скопіювати разом з учасниками та правилами, але без старих призначень і статистики;
- аналітика справедливості показує навантаження, чергування у вихідні, середній відпочинок і повтори пар;
- клік по порожній клітинці швидко призначає чергування; клік по зайнятій відкриває окремі команди для позначення виконання та зняття призначення;
- правий клік відкриває «А», відсутності, жовту заборону планування без впливу на статистику та примусове зняття чергування;
- можна вибрати будь-який тиждень за датою або перейти до першого незаповненого; попередній перегляд передує застосуванню, готові дні та ручні призначення не перераховуються;
- вибраний тиждень можна очистити повністю або прибрати лише автоматичні призначення зі збереженням ручних і реалізованих; дію можна скасувати; обидва режими стосуються тільки активного графіка й залишають «А», відсутності, заборони та правила;
- циклічний генератор продовжує чергу після вручну внесеної історії, вирівнює навантаження всередині нового тижня, компенсує два чергування тим, хто мав одне попереднього тижня, не пропускає доступних учасників і починає нове коло з 1 січня;
- окрема сторінка «Відпросився» з датою, точним часом виходу й повернення, автоматичною тривалістю, напрямком/причиною та приміткою; є фільтри за працівником, періодом і текстом причини; ці короткі відлучення не змінюють табель і відпрацьовані дні;
- відлучення можна редагувати; програма не дозволяє записати два відлучення однієї людини з часом, що перетинається;
- у віджеті є режим списку, у табелі й графіку можна переходити між клітинками стрілками та відкривати дії клавішею Enter;
- аналітика показує помісячну динаміку та експортує звіт за вибраний період;
- повний імпорт/експорт резервної копії JSON і табличний експорт CSV, включно з усіма окремими графіками та журналом «Відпросився»;
- у налаштуваннях можна переглянути й відновити локальну резервну копію; при пошкодженні основного файлу програма перевіряє попередню та щоденні копії, зберігаючи пошкоджений файл окремо;
- повне обнулення всіх локальних даних із подвійним підтвердженням.

Днями роботи вважаються дні з активною роботою, підтверджені відпрацьовані дні та «Інша робота». Особисті справи, лікарняний, відпустка, відгул та святкові дні показуються окремо і не збільшують лічильник відпрацьованих днів.

Тиждень із порожнім місцем у чергуваннях лишається в черзі для повторного перегляду. Якщо доступність людей змінилася, неповний автоматичний день можна сформувати повторно: попередній автоматичний вибір дозволено замінити, а внесених вручну чергових і повністю готові дні генератор не чіпає. Уже призначеного на завтра працівника генератор не ставить сьогодні, якщо діє заборона чергувань поспіль. Заблокований вручну тиждень пропускається під час пошуку наступного тижня.

Наведений нижче порядок розподілу описує початкові правила. У вікні «Правила графіка» можна змінити кількість людей, обмеження й пріоритети; для перебудови готових днів спочатку очистіть тиждень.

У графіку чергувань календарні вихідні залишаються звичайними днями графіка. Працівник не потрапляє до розподілу, якщо його виключено зі складу учасників або для нього позначено вихідний, відпустку, лікарняний, відгул, особисті справи, «А» чи жовту заборону планування. Жовта позначка не є відсутністю та не входить до жодної статистики. Після «А» чергування наступного дня дозволене, але після чергування не можна ставити «А» на наступний день. Якщо «А» уже внесено, програма не призначить цю людину черговою напередодні. Генератор продовжує циклічну чергу за останніми вручну внесеними чергуваннями, тимчасово пропускає відсутнього та повертає його в чергу після появи. Автоматичне призначення однієї людини два календарні дні поспіль заборонене жорстко. Так само генератор не ставить людину у два сусідні календарні вікенди; якщо склад без такого повтору неможливий, місце лишається порожнім. Увесь новий календарний тиждень оптимізується одним блоком, щоб ранні призначення не створювали штучної нестачі наприкінці тижня. Якщо через жорсткі правила другого допустимого чергового немає, програма залишає місце порожнім і підсвічує всю колонку дня червоним. Натискання на цю колонку відкриває склад дня: там можна додати другого працівника або явно дозволити чергування одного. Ручні призначення є незмінними обмеженнями моделі: генератор може лише заповнити вільне друге місце, але ніколи не прибирає й не замінює обрану вручну людину. Готові автоматичні дні також не перераховуються повторним натисканням кнопки. Стара різниця в кількості не виключає працівника з нового кола. Якщо працівник мав одне чергування в попередньому календарному тижні, модель надає йому пріоритет на два в наступному; при цьому тижневий розподіл усе одно не повинен мати різницю понад одне чергування за достатнього складу. Історія пар у поточному році враховується під час кожного нового формування, тому модель спершу шукає ще не використані поєднання співробітників і лише за відсутності рівноцінної альтернативи повторює пару. Модель лексикографічно мінімізує: кількість порожніх місць, нерівність кількості чергувань у новому тижні, невиконану компенсацію попереднього тижня, порушення двох повних днів відпочинку, повтор уже використаної пари та відхилення від циклічної черги. Тобто рівномірність має вищий пріоритет за бажаний дводенний проміжок, але заборона двох календарних днів поспіль завжди залишається жорсткою. За восьми доступних учасників і 14 тижневих місць результатом мають бути шість людей із двома чергуваннями та двоє з одним, якщо ручні позначки й відсутності не роблять це неможливим. Статистика, історія пар і черга рахуються окремо для кожного календарного року; при переході року контрольна дата переноситься на 31 грудня, тому вже внесені січневі чергування не губляться.

## Запуск для розробки

Потрібен Node.js 24 або новіший.

```bash
npm install
npm test
npm start
```

## Збірка для Windows

```bash
npm install
npm run dist:win
```

У каталозі `dist` буде створено переносимий файл `Counter.exe`, який не потребує інсталятора. У GitHub Actions він завантажується як артефакт `Counter`.

## Зберігання даних

Поруч із переносимим `Counter.exe` автоматично створюється папка `Counter-data`. У ній розміщуються основний файл `counter-data.json`, попередня резервна копія та налаштовувана кількість щоденних копій у папці `backups`. Під час першого запуску нової версії наявна база зі старого системного каталогу Windows автоматично копіюється до цієї папки. Для додаткової резервної копії або перенесення між комп'ютерами можна використовувати експорт та імпорт JSON.
